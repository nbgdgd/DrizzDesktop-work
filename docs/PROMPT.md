## На чём экономим и почему это не ухудшает результат

1. **Контекст проекта — один раз, в `CLAUDE.md`.** Файл читается в начале каждой сессии, поэтому в промте не нужно пересказывать архитектуру и команды. Документация советует держать его коротким: лишние строки размывают важные правила.
2. **Одна задача — одна сессия.** Между несвязанными задачами — `/clear`. Длинная сессия с чужим контекстом стоит дороже на каждом сообщении и работает хуже.
3. **Конкретика вместо «улучши».** Файл, симптом, что считается «готово». Размытый запрос заставляет читать весь проект.
4. **Проверка, которую Claude может запустить сам:** тест, `tsc`, скриншот. Opus 5 проверяет свою работу без напоминаний, поэтому фразы вроде «перепроверь дважды» и «запусти субагента для проверки» только тратят токены — их не пишем.
5. **Рамки объёма.** Opus 5 склонен расширять задачу; одна фраза про объём это останавливает.
6. **Короткий отчёт.** Ответы Opus 5 по умолчанию длинные; просьба о кратком итоге заметно их сокращает.
7. **Структура тегами** (`<task>`, `<done>`…), если в промте несколько частей: модель не путает задачу с контекстом.
8. **Если поправлять пришлось дважды** — `/clear` и новый промт с учётом ошибки: так выходит дешевле, чем тянуть испорченный контекст.

## Шаблон

```text
<task>
{что сделать, одним-двумя предложениями; где: файлы или модули}
</task>
<why>
{зачем: что видит пользователь сейчас и что должен видеть}
</why>
<done>
{как проверить: команда теста, сценарий в tools/preview-*.cjs или новый тест в src/scenarios.test.ts}
</done>
Объём: сделай ровно это. Если запрос выглядит ошибочным или есть способ лучше — скажи одной фразой и сделай, как просили. Коммит и пуш в текущую ветку.
Итог — 3–5 строк: что изменено, чем проверено, что не проверено.
```

## Примеры (задачи условные)

**Баг:**
```text
<task>При масштабе Windows 175 % облачко реплики обрезается сверху (balloon.ts, layout.ts).</task>
<why>Верхняя строка текста не видна, когда питомец стоит на панели задач.</why>
<done>Тест в src/regression.test.ts для dpr 1.75; npm test зелёный; скриншот tools/preview-scenes.cjs с deviceScaleFactor 1.75.</done>
Объём: только это. Итог — 3 строки.
```

**Новое поведение:**
```text
<task>Если пользователь 10 минут подряд двигает окна, питомец прячется за край экрана и выглядывает (antics.ts, по образцу scare()).</task>
<why>Хочу, чтобы суета на экране его пугала.</why>
<done>Сценарий в src/scenarios.test.ts (describe "antics"); npx tsc --noEmit; tools/preview-scenes.cjs — кадр с выглядыванием.</done>
Объём: без новых настроек, реплики — 6 штук в lines.ts в тоне Drizz. Итог — 5 строк.
```

**Интерфейс:**
```text
<task>В src/panel/pages/Home.tsx добавь карточку «Сегодня»: сколько раз кормили, гладили, бросали за день (данные есть в game.life.recent).</task>
<done>tools/preview-panel.cjs, скриншот вкладки status; tsc.</done>
Объём: только Radix-компоненты, без новых зависимостей. Итог — 3 строки.
```

## Ещё несколько приёмов

- Большая задача с неясным решением: сначала план (`Shift+Tab` → plan mode), потом реализация в новой сессии по готовому плану.
- Поиск по многим файлам — через субагента («используй субагента, чтобы найти…»): его чтение не засоряет основной контекст. Для мелких правок субагенты не нужны.
- Для рутинных правок — Sonnet или меньший effort; Opus на высоком effort — для архитектуры и сложных багов.
- Картинки (скриншоты с Windows) прикладывайте прямо в сообщение: это дешевле, чем описывать словами.
