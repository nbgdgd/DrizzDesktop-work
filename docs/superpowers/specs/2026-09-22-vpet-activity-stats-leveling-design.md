# Drizz Desktop: активность как в VPet, статистика программ, прокачка

Дата: 2026-09-22. Проект: `Downloads\DrizzDesktop-work\DrizzDesktop` (Tauri 1.8 / React 18 / Phaser 3.90, без git).

## Цели

1. Питомец живее: реагирует на клики, скролл и печать в любых программах, чаще бегает, чаще показывает анимации и реплики. Реплик намного больше — «просто так» и за действия, с матом (стиль проекта).
2. Статистика: сколько времени пользователь провёл в каждой программе (сегодня / 7 дней / 30 дней / всего). Питомец иногда сообщает лидера дня.
3. Прокачка по модели VPet (LorisYounger/VPet, Apache-2.0): опыт, уровень, настроение, бодрость, сытость, жажда, здоровье, симпатия, деньги, магазин еды с графикой из VPet (разрешено для некоммерческого использования при указании источника и ссылки).

Вне цели: сетевой чат, новые персонажи, изменение AniBlaze/TimePet.

## 1. Глобальный ввод (`native.rs`, `observe.rs`)

- В `hook_thread` (там уже есть цикл сообщений) ставятся `SetWindowsHookExW(WH_MOUSE_LL)` и `WH_KEYBOARD_LL`.
- Колбэки только инкрементируют атомарные счётчики: `clicks`, `rightClicks`, `wheel`, `keys`; для клика сохраняют экранные координаты и время `lastClick {x, y, t}`. Коды клавиш не читаются и не сохраняются (только факт `WM_KEYDOWN`).
- Клики по окну самого питомца пропускаются (`WindowFromPoint` + `GetWindowThreadProcessId` == свой pid).
- Настройка `observeInput` (по умолчанию `true`, вкладка «Приватность»). При `false` колбэки возвращаются сразу без счёта.
- Snapshot получает поле `input: { clicks, rightClicks, wheel, keys, lastClick: { x, y, t } | null }` (кумулятивные u64). Snapshot идёт раз в 1 с, этого достаточно.

## 2. Реакции на ввод и «живость» (`director.ts`, `PetScene.ts`, `dialogue.ts`)

Director считает дельты счётчиков между снимками и держит скользящие окна.

Новые события (правило: action, priority, cooldown):

| событие | условие | действие |
|---|---|---|
| `typing` | ≥ 40 нажатий за 10 с | look, 4 мин |
| `typingLong` | печать без паузы > 20 с дольше 3 мин | look, 15 мин |
| `afterBurst` | всплеск печати закончился (45 с тишины), шанс 30 % | wave, 6 мин |
| `clicking` | ≥ 8 кликов за 5 с | look, 3 мин |
| `scrolling` | ≥ 30 тиков колеса за 8 с | look, 4 мин |
| `rightClick` | правый клик вне питомца, шанс 15 % | look, 5 мин |
| `glance` | любой клик, шанс 25 %, без реплики | look 1.2 с, 8 с |
| `curious` | клик дальше 900 px от питомца или на другом мониторе, шанс 20 % | идёт к x клика (`world.go`), реплика, 2 мин |

Частота реплик. Сейчас все не-direct реплики режутся общим порогом `commentMinutes` (7 мин) — отсюда редкость. Меняется так:

- Общий порог применяется только к «фоновым» событиям: `chatter`, `idle`, `night`, `long`, `cursor`, `stats`, `hungry`, `thirsty`, `tired`.
- Реакции на действия (ввод, клики, сборки, окна, медиа, уровень) ограничены своим cooldown и общим антиспамом 20 с.
- `commentMinutes` по умолчанию 7 → 3.

`chatter` — реплики «просто так»: PetScene раз в `commentMinutes × 60000 × random(0.6..1.3)` мс, пока пользователь за ПК. Банк ≥ 60 строк.

Бродяжничество (`PetScene`): пауза между активностями calm 25 с / balanced 9 с / active 4 с (было 35/20/10), дистанция прогулки ±450 px (было ±300), вероятность прогулки выше; паузу дополнительно делит `1 + 0.03 × уровень` (максимум ×0.6). В набор idle-действий добавлены `jump` (10 %) и `celebrate` (5 %, только при настроении ≥ 75).

Реплики: к каждому существующему банку +4–8 строк; новые банки для всех событий выше и для разделов 3–4 (`typing`, `typingLong`, `afterBurst`, `clicking`, `scrolling`, `rightClick`, `curious`, `chatter`, `stats`, `statsDay`, `levelUp`, `hungry`, `thirsty`, `tired`, `sad`, `happy`, `sick`, `fed`, `broke`). Стиль Drizz: грубый, с матом. Для claude/aqua-wisp `gentle` добавляет по 2 мягкие строки на `chatter`, `typing`, `stats`, `levelUp`, `fed`; остальное — как сейчас, общий банк.

## 3. Статистика программ (`usage.rs`, вкладка «Статистика»)

- `usage.rs`: цикл снимков уже знает exe переднего окна. Каждую секунду при `idle < 60 с`, не locked — `days[date][exe] += 1`. Запись в `%LOCALAPPDATA%\DrizzDesktop\usage.json` раз в 60 с и при выходе. Хранится 90 дней.
- Команда `usage_stats()` → `{ today, week, month, all: [{ app, seconds }] }` (по убыванию). Команда `usage_clear()`.
- Snapshot получает `usage: { today: [{ app, seconds }] }` — топ-5 за сегодня, для реплик.
- Настройка `trackUsage` (по умолчанию `true`) во вкладке «Приватность»; при `false` не считает и не пишет.
- Имена: карта exe → человеческое имя (chrome.exe → Chrome, code.exe → VS Code, msedge.exe → Edge, firefox.exe → Firefox, discord.exe → Discord, telegram.exe → Telegram, explorer.exe → Проводник и т.д., ~30 записей), иначе имя без `.exe`.
- События: `stats` — раз в 90–150 мин присутствия, шаблон с `{app}` и `{time}` («Ты сегодня {time} сидишь в {app}, охуеть»); `statsDay` — первый снимок после 21:00, итог дня. Время форматируется «2 ч 15 мин» / «40 мин».
- Вкладка «Статистика»: переключатель периода, таблица имя / время / полоска доли, кнопка «Очистить».

## 4. Прокачка (`game.ts`, вкладки «Статус» и «Магазин»)

Состояние `Game` хранится в Store как новое поле `game` (Rust `Store.game: Value`, команда `save_game`):

```
{ exp, money, strength, food, drink, feeling, health, likability,
  storeStrength, storeFood, storeDrink, lastTick, level }
```
Начальные значения как в VPet: `money 1000, exp 0, strength 100, food 100, drink 100, feeling 60, health 100, likability 0`.

Формулы VPet: `level = floor(sqrt(exp)/10) + 1`; до апа `(level×10)²`; `likabilityMax = 90 + level×10` (излишек уходит в здоровье); режим (`CalMode`) → `happy | normal | poor | ill`.

Тик раз в минуту (в `PetScene`, по `now`; при возврате после сна ПК догоняет не больше 8 часов; при отсутствии пользователя (`idle > 5 мин`) множитель распада 0.25 и без опыта/денег):

- `exp += 1`; при `feeling ≥ 75`: `exp += 2`, `health += 1`; при `feeling ≥ 90`: `likability += 1`; при `feeling ≤ 25`: `likability −= 1`, `exp −= 1`.
- `feeling −= 0.15`; музыка играет → `+0.1`.
- `food −= 0.4`, `drink −= 0.6`; при `food ≤ 25` или `drink ≤ 25`: `health −= 1`.
- `strength −= 0.3` бодрствуя; `+2` пока питомец `sleep`/`rest`.
- `money += 1.5 × (1 + 0.1×level)` пока пользователь активен.
- `storeTake()`: десятая часть отложенных значений переносится в статы (как в VPet).
- Взаимодействия: клик `feeling +2` (не больше 3 кликов в минуту), poke `−1`, drag `−0.5`, summon `+1`, `build-success` / `render-done` / `download-done` `money +20`, `feeling +5`.
- `levelUp`: реплика, `celebrate`, bubble «LVL N».

Влияние на поведение: `ill`/`poor` — базовое действие чаще `rest`, пауза бродяжничества ×2; `happy` — пауза ×0.7; `strength < 20` → `rest`; `food < 25` → `hungry` каждые 20 мин; `drink < 25` → `thirsty`; `health < 50` → `sick`; `money` не хватает при покупке → `broke`.

Магазин: ~24 предмета, перенесённых из `mod/0000_core/food/food.lps` VPet (напитки, снеки, еда, функциональные, лекарство) с русскими названиями, ценой и эффектами (`Exp, Strength, StrengthFood, StrengthDrink, Health, Feeling`). Покупка = `EatFood` VPet: половина эффекта сразу, половина в `store*`. Иконки — PNG из `VPet-Simulator.Windows/mod/0000_core/image/food/` в `public/shop/`. Упоминание в `THIRD_PARTY.md` и внизу вкладки: «Иконки еды — VPet (LorisYounger), https://github.com/LorisYounger/VPet».

Вкладка «Статус»: уровень и полоса опыта, деньги, полоски настроения / бодрости / сытости / жажды / симпатии, текст режима (здоровье не показывается, как в VPet — только через режим «болеет»).

## Ошибки и отказ

- Хук не установился (`SetWindowsHookExW` вернул 0) — запись в диагностику, счётчики остаются 0, остальное работает.
- `usage.json` повреждён — начинаем с пустого, старый файл переименовывается в `usage.bad.json`.
- Поле `game` отсутствует или битое — `cleanGame` возвращает начальные значения, как `cleanSettings`.
