# Статус проверки — 2026-09-21

Продолжение работы над исходниками 0.1.0 от 2026-09-20. Это самостоятельный проект, не изменение AniBlaze или TimePet. Все проверки ниже выполнены на Windows 11 Pro 10.0.26200 x64, два монитора 2560×1440 и 1920×1080, оба 125 %, WebView2 Runtime 153.0.4234.48. Реальной Windows 10 в распоряжении не было.

## Подтверждённые причины и исправления

1. **Персонаж невидим, видны только реплики.** Воспроизведено на release-EXE через порт отладки WebView2 (`tools/cdp-probe.cjs`): `Connecting to 'https://tauri.localhost/pets/drizz/spritesheet.webp' violates the following Content Security Policy directive: "connect-src ipc: http://ipc.localhost …"`. Phaser 3.60+ грузит изображения XHR-ом как blob, а `connect-src` в `tauri.conf.json` не содержал `'self'`. Все пять атласов блокировались, спрайт получал текстуру `__MISSING` (зелёный квадрат 32×32), попиксельная маска силуэта была пустой, регион окна включал только прямоугольник пузыря — поэтому реплики были видны, а персонаж нет. В dev-сервере и headless-превью CSP не применяется, поэтому старые проверки «сцена запускается» этого не ловили. Исправлено: `'self'` в `connect-src`; дополнительно Phaser переведён на `imageLoadType: "HTMLImageElement"` (без XHR/blob). Проверено: после одной только правки CSP спрайт появляется на реальном рабочем столе (`tools/desktop-shot.ps1`, снимок физических пикселей окна).
2. **Провал расширенного drag-теста из прошлого отчёта** (ступни 1381 вместо 350) — следствие пункта 1: регион состоял из пузыря, синтетическое нажатие попадало в текст, а не в персонажа. После исправления `tools/native-drag-check.ps1` проходит целиком: реальное перетаскивание на верхний край окна, следование за перемещённым окном, падение при сворачивании, скрытие в полном экране, возврат после него, фокус не украден.
3. **Спам предупреждений** `Texture "__MISSING" has no frame` 30 раз в секунду — следствие пункта 1; теперь отсутствие/несоответствие атласа проверяется в `changePet()`, персонаж не рисуется, а в пузыре показывается причина, одна запись в консоли и в диагностике.
4. **Масштаб Windows.** Холст Phaser был 360×340 CSS-пикселей независимо от DPI (размытие при 125 %+), а масштаб региона брался из DPI монитора под ногами, а не из фактического DPI окна. Теперь холст = 360×340 × `devicePixelRatio` (`src/dpi.ts`), камера сцены с zoom = DPR, текст реплик с `resolution` = DPR (учтена особенность Phaser: `Text.setResolution()` не обновляет `frame.source.resolution`, без этого текст рисовался в 1,25 раза крупнее — видно на промежуточном снимке), регион и размер окна считаются по DPR, `pose` возвращает DPI, назначенный Windows, расхождение пишется в диагностику. Ручной размер остаётся логическим поверх системного масштаба. Проверено аппаратно `tools/dpi-switch-check.ps1`: смена масштаба основного монитора 125 → 150 → 100 → 125 %: окно 450×425 → 540×510 → 360×340 → 450×425, холст следует за DPR, расхождение DPI держится один кадр (~80 мс), персонаж остаётся на панели задач, не обрезан и не исчезает (снимки `tools/dpi-*.png` при запуске).
5. **DPI awareness и Windows 10.** Добавлен манифест приложения (`src-tauri/build.rs`): `dpiAwareness PerMonitorV2`, `supportedOS` Windows 10/11, `asInvoker`. Убраны дублирующие `SetProcessDpiAwarenessContext` в `main.rs` и `SetThreadDpiAwarenessContext` в `native.rs` (tao делает то же при создании цикла событий; манифест действует раньше). Наличие манифеста в EXE проверено по содержимому файла.
6. **Потеря персонажа.** Пункт трея и кнопка в настройках «Вернуть персонажа на экран» (`recenter`): ставит питомца на пол монитора под курсором (или выбранного/основного), сбрасывает опору и скорость, снимает ручное скрытие, сохраняет только позицию. Проверено через IPC (`--recenter` в probe, запись `recenter: \\.\DISPLAY2 -> 2410,1380`).
7. **Старые настройки.** `storage::load` теперь разбирает файл терпимо: отсутствующие ключи, лишние ключи, повреждённая строка не приводят к сбросу всего; полностью нечитаемый файл копируется в `state.corrupt.json` перед заменой. Проверено запуском собранного EXE из `C:\` с профилем «старой версии» (`tools/legacy-profile.cjs`: персонаж nezukocoder, размер 140, факты, токен, позиция 9000/-5000 на несуществующем мониторе, предпочтительный монитор DISPLAY9): персонаж отрисован с размером 140, настройки, факты и токен сохранены, позиция восстановлена на доступный монитор.
8. **Поведение.** Прямое касание (клик/перетаскивание) будит спящего или отдыхающего персонажа сразу (`Director.wake`), не дожидаясь следующего снимка бездействия. Добавлены реплики с характером для click/poke/drag/dragged/return/editor/gameEnd/long/switching/alternating/windowMove/fall/idle/summon/hello/mediaPause; мат и оскорбления не смягчались.
9. **Горячие клавиши.** `GlobalShortcutManager` tao/Tauri 1 на этой машине сообщал успех для `Ctrl+Alt+D`, но сочетание не срабатывало (проверено SendInput с записью в диагностику), а `Ctrl+Alt+C` отвергался («Unable to register accelerator with RegisterHotKey»), хотя из другого процесса оба сочетания регистрировались свободно. Регистрация перенесена в поток хуков (`native.rs`): `RegisterHotKey` с явными id 1/2, обработка `WM_HOTKEY` в существующем цикле сообщений, отчёт о результате в диагностике. Проверено: обе комбинации регистрируются и срабатывают (`hotkey 1 fired` → позвать, `hotkey 2 fired` → окно разговора).
10. **Размер и сглаживание (запрос пользователя по ходу работы).** Размер по умолчанию 116 → 76 логических пикселей (около 100 физических при 125 %, как на присланном образце), минимум ползунка 56. Добавлена настройка «Сглаживание» (по умолчанию включена): `imageSmoothingQuality = "high"` на контексте холста (заново после каждого изменения размера холста, поскольку смена `canvas.width` сбрасывает контекст) и LINEAR/NEAREST-фильтр текстуры. Явно сохранённый пользователем размер не меняется.
11. **Диагностика.** Настройка «Диагностика в файл» / флаг `--diag`, файл `diagnostic.log` с ротацией 1 МБ и атомарной записью строк (несколько потоков): ресурс, кадры, состояние (только при смене), позиция окна (не чаще раза в 3 с), DPR, назначенный DPI, причина скрытия, мониторы, регистрация горячих клавиш, каждое нажатие в окне, начало и конец перетаскивания с координатами курсора, причина, по которой после падения персонаж не сел на окно (`perch:`). По умолчанию выключено.
